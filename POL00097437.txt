My understanding is that when AP’s fail there is a way to recover these on horizon.
[Gil] Not normally. Most AP transactions are not recoverable. There are some AP-ADC scripts that are recoverable
such as Postal Order sales / encachments. (As these are all under POL’s control, I can’t give a full list.)

Recoverable transactions are:

1. Online Banking transactions

2. ETop Ups

3. Selected AP ADC scripts {as above}. Note these usually produce immediate receipts rather than waiting for
them to be printed out at settlement.

4, Plastic payments (though refunds will be calculated where non recoverable transactions are cancelled)

Would the user have to re-boot the system?
[Gi] Not normally. Really need to consider the type of failure. There are two broad categories:
1. Where the terminal fails at some point while service a customer

In this case the terminal probably does need to be rebooted as it has failed. Also there is no help from the
terminai as to exactly what to do for the current customer {as it has failed!}. in simple terms, ali recoverable
transactions should be assumed to have worked OK while all non-recoverable transactions should be assumed
to have failed,

2. Where there is a failure to communicate with the Data Centre during the settlement process {ie after
everything is paid for but before the receipts are printed)

In this case after Cancelling following one or more reties, the system should produce a Disconnected Session
receipt making it clear which transactions were recoverable and so should be considered to be successful and
which were not and se should be considered not te have happened. This information should be used in
communication with the customer. Specifically no AP receipts will be generated at settlement time in this
scenario,

[Gi] Unlike the old Horizon system there is no specific AP recovery when restarting after a failed session.

There may be prompts on the screen as a result of running various recovery scripts and in particular if an AP ADC
transaction is recoverable, then a special recovery script is run as part of the recovery process.

Would the office be clear that they have had to run AP recovery or would it run automatically without their knowledge?
[GU] Recovery is always run automatically the next time the terminal is Logged On. NB it must be the same logical
terminal 9er Node iD}, but if the physical terminal has been replaced Sie a box swap then recovery is still invoke, but
there may be questions to the class regarding the last successful session {this is held on the hard disk and so not
available if the box has been swapped)

How long would this take?

[GU] It is pretty quick. It really depends on the recovery script.

How would the transaction show on the system once recovered?

[G13] It would show as a normal transaction for Credence. it is marked in the audit trail as having been recovered.
Would the horizon create an existing reversal on the system and how would this show on credence/at the office?

The basket has no recoverable transactions

The settlement information is sent from the counter to the Data Centre

it is successfully recorded in the Data Centre

The response foils to get back to the counter

Subsequent reties fail

The customer is told that the transaction has failed and given their money back

On the next Log On recovery takes place. Recovery will detect that the Basket had been recorded and then
generate an existing reversal for everything in the basket as the counter should have assumed that it had
failed.
